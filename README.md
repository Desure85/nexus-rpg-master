# Nexus RPG — онлайн-НРИ с ИИ-мастером

Настольная ролевая игра в браузере, где мастером выступает ИИ. Есть три режима:

| Режим | Для чего |
|---|---|
| **Соло** | Вы и ИИ-мастер: один герой или целая партия, которой вы управляете сами. |
| **С друзьями (онлайн)** | Каждый игрок заходит по ссылке со своего телефона, занимает героя и шлёт ходы (с честным серверным броском). Мастер подтверждает раунд, и ИИ отвечает всем сразу. Текст стримится всем в реальном времени. |
| **Сказка** | Интерактивная сказка с выборами без кубиков и цифр. Можно выбрать возраст (3–5, 6–8, 9–12, взрослые), число глав и мораль. Друзья и дети предлагают продолжения со своих устройств, а в конце получается книга (Markdown / печать в PDF). |

Для RPG-режимов можно выбрать формат «партия на вечер» или «кампания» (идл-доход, логово, экспедиции, фронты) и стиль: Narrative, Balanced, Combat или детская сказка.

## Быстрый старт

### Docker (рекомендуется)

```bash
cp .env.example .env      # впишите ключ ИИ и APP_SECRET
docker compose up -d --build
# http://localhost:3000
```

База SQLite лежит в `./data/game.db`. Для бэкапа достаточно скопировать этот файл, лучше при остановленном контейнере или через `sqlite3 game.db ".backup backup.db"`.

### Без Docker

```bash
npm ci
cp .env.example .env
npm run build
npm start            # production: http://localhost:3000
```

Режим разработки с hot reload: `npm run dev`.

Попробовать без ключей ИИ и без оплаты: `LLM_PROVIDER=mock PAYMENTS_PROVIDER=mock npm run dev`, затем зарегистрируйтесь — первый аккаунт станет администратором. Демо-провайдер отвечает заготовками, и на нём видно весь интерфейс и мультиплеер.

## ИИ-провайдеры

Все запросы к ИИ идут **с сервера**, ключи в браузер не попадают.

| Провайдер | Переменные |
|---|---|
| Gemini | `GEMINI_API_KEY`, `GEMINI_MODEL` |
| OpenRouter | `OPENROUTER_API_KEY`, `OPENROUTER_MODEL` |
| OpenCode (подписка) | `OPENCODE_API_KEY`, `OPENCODE_MODEL` |
| Локальная / любая OpenAI-совместимая (Ollama, LM Studio, vLLM) | `LOCAL_MODEL_URL`, `LOCAL_MODEL_KEY`, `LOCAL_MODEL_NAME` |
| Демо без ИИ | `LLM_PROVIDER=mock` |

ИИ платформы настраивается в «Администрирование → ИИ платформы»; каждое пространство может подключить и свой ключ. Переменная `LLM_PROVIDER` жёстко фиксирует провайдера.
Если модель запущена на той же машине, что и Docker, укажите адрес `http://host.docker.internal:11434/v1`.

## Пространства, аккаунты и монетизация

- **Аккаунты мастеров**: вход по email и паролю (scrypt), сессия в httpOnly-cookie, защита от CSRF. Игрокам аккаунт не нужен: они заходят по ссылке на героя.
- **Пространства (тенанты)**: клуб, семья или команда. В каждом свои мастера, игры, ИИ и баланс. Роли:
  - **Владелец** — всё, включая оплату;
  - **Админ** — участники, ИИ, все игры пространства;
  - **Мастер** — свои игры, игры коллег видит, но не меняет.

  Приглашение — ссылка `/invite/…`, действует 7 дней и до 10 регистраций.
- **Первый зарегистрированный пользователь становится администратором платформы** (или те, кто указан в `SUPERADMIN_EMAILS`). Режим регистрации задаёт `REGISTRATION`: `open`, `invite` или `closed`.
- **ИИ пространства**:
  - **Свой ключ (BYOK)** — Gemini, OpenRouter или OpenCode. Ключ хранится зашифрованным (AES-256-GCM, `APP_SECRET`), в API отдаётся маской. Кредиты не тратятся.
  - **ИИ платформы** — ваш серверный ключ, расход списывается **кредитами** по фактическим токенам провайдера. 1 кредит = `CREDIT_TOKENS` взвешенных токенов, вывод в `OUTPUT_WEIGHT` раз дороже, ход мастера ≈ 10 кредитов.
- **Тарифы**:
  - «Бесплатный»: до 4 героев и игроков, `FREE_MAX_SESSIONS` сессий, `FREE_CREDITS` приветственных кредитов;
  - «Мастер» (подписка): до 8 героев и игроков, 500 сессий.

  Продаются пакеты кредитов и подписка, состав меняется через `BILLING_PRODUCTS` (JSON).
- **Оплата — ЮKassa** (`PAYMENTS_PROVIDER=yookassa`). Вебхук `POST /api/billing/webhook/yookassa` указывается в личном кабинете ЮKassa на событие `payment.succeeded`. Вебхуку не доверяем: статус перепроверяется запросом к API ЮKassa, зачисление идемпотентно. Чеки по 54-ФЗ включаются через `YOOKASSA_RECEIPT=true`. Для разработки есть `PAYMENTS_PROVIDER=mock`: оплата одним кликом.
- **Администрирование платформы** (в меню слева): пространства, выручка, расход за 30 дней, ручное начисление кредитов, включение тарифа, блокировка пространства, ИИ платформы.
- Защита от SSRF: свой URL модели в BYOK разрешён только при `ALLOW_BYOK_CUSTOM_URL=true` (self-host).
- Лимиты запросов к ИИ считаются по пользователю, попытки входа — по IP. За реверс-прокси включите `TRUST_PROXY=true`.

Старые сессии, созданные до появления аккаунтов, автоматически переходят в пространство первого администратора платформы.

## Как это устроено

```
браузер мастера ─┐                        ┌─ LLM (Gemini/OpenRouter/OpenCode/локальная)
телефоны игроков ┼─ REST + WebSocket ─ сервер ┤
                 │   (стрим, события)        └─ SQLite (сессии, состояние движка)
```

- `server/engine.ts`: игровой ход целиком на сервере. У каждой сессии своя очередь ходов, поэтому одновременные действия не затирают историю. Движок собирает промпт, добавляет честную проверку встречи и `[STATE]`, стримит ответ всем в комнате, разбирает JSON-блоки, применяет урон, золото и XP (State Authority), а при повышении уровня запускает отдельный ход со способностями.
- `server/tenancy.ts`: аккаунты, пространства, роли, приглашения, BYOK. `server/billing.ts`: кредиты, тарифы, ЮKassa, суперадмин.
- `shared/oracle.ts`: оракул вариативности (слоты действий, мотивы, идеи глав).
- `server/game.ts`: экономика, лут, база, экспедиции, фронты, мемориал, idle.
- `server/llm.ts`: провайдеры со стримингом и таймаутами, `server/mock-llm.ts` — демо и тесты.
- `shared/`: правила и промпты, парсеры ответов модели, серверные броски. Этот код общий для клиента и сервера.
- `src/`: React-клиент: экран мастера (`App.tsx`) и экран игрока (`components/CharacterView.tsx`).

## Разработка

```bash
npm run lint     # tsc --noEmit
npm test         # vitest: парсеры, движок, e2e API (соло, мультиплеер, сказка, аккаунты, пространства, биллинг)
npm run build    # vite (клиент) + esbuild (сервер) → dist/, dist-server/
```

CI в GitHub Actions прогоняет lint, тесты, сборку, smoke-тест production-сборки и сборку Docker-образа.
