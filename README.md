# Nexus RPG — онлайн-НРИ с ИИ-мастером

Настольная ролевая игра в браузере, где мастером выступает ИИ. Есть три режима:

| Режим | Для чего |
|---|---|
| **Соло** | Вы и ИИ-мастер: один герой или целая партия, которой вы управляете сами. |
| **С друзьями (онлайн)** | Каждый игрок заходит по ссылке со своего телефона, занимает героя и шлёт ходы (с честным серверным броском). Мастер подтверждает раунд, и ИИ отвечает всем сразу. Текст стримится всем в реальном времени. |
| **Сказка** | Интерактивная сказка с выборами без кубиков и цифр. Можно выбрать возраст (3–5, 6–8, 9–12, взрослые), число глав и мораль. Друзья и дети предлагают продолжения со своих устройств, а в конце получается книга (Markdown / печать в PDF). |

Для RPG-режимов можно выбрать формат «партия на вечер» или «кампания» (идл-доход, логово, экспедиции, фронты) и стиль: упор на сюжет, баланс, упор на бои или детская сказка.

## Демо

**[desure85.github.io/nexus-rpg-master](https://desure85.github.io/nexus-rpg-master/)** — играбельная версия без сервера и ключей.

Это та же игра: серверный код (`server/api.ts`) запускается прямо во вкладке браузера, SQLite заменяет sql.js (WebAssembly), данные лежат в IndexedDB. Вместо ИИ отвечает «рассказчик-заготовка» (`MOCK_STYLE=demo`), который читает действия игроков и подсказки оракула и выдаёт настоящие теги механик — урон, добычу, опыт, предметы. Оплата тестовая. Мультиплеер работает между вкладками одного браузера: откройте ссылку на героя в соседней вкладке.

**Свой ключ ИИ в демо.** «Пространство → ИИ → Свой ключ»: Gemini, OpenRouter или локальная модель (Ollama с `OLLAMA_ORIGINS`). Запросы идут из браузера напрямую провайдеру. Ключ не попадает в базу демо: по умолчанию он живёт только в памяти вкладки, а с галочкой «Запомнить на этом устройстве» хранится в IndexedDB, зашифрованный неизвлекаемым ключом WebCrypto. CSP страницы разрешает соединения только с провайдерами ИИ. opencode из браузера недоступен (CORS) — только на своём сервере. Собрать локально: `npm run build:demo` (результат в `dist-demo/`), запустить в режиме разработки: `npm run dev:demo`.

## Быстрый старт

### Docker (рекомендуется)

```bash
cp .env.example .env      # впишите ключ ИИ и APP_SECRET
docker compose up -d --build
# http://localhost:3000
```

База SQLite лежит в `./data/game.db`. Сервер сам делает онлайн-бэкап раз в сутки в `./data/backups` и хранит последние 7 (`BACKUP_INTERVAL_HOURS`, `BACKUP_KEEP`, `BACKUP_DIR`); копируйте их на другой диск или в облако. Вручную: `sqlite3 game.db ".backup backup.db"`.

Гостям открывается лендинг (режимы игры, миры каталога, вопросы); ссылка `/world/<id>` показывает мир и отдаёт og-теги с названием, описанием и обложкой — превью в VK и Telegram. `sitemap.xml` и `robots.txt` строятся от `APP_URL`. Воронка — в «Администрировании» → «Воронка»: заходы → регистрации → начали игру → 3+ хода → вернулись → оплатили, по источникам (`?utm_source=` или `?ref=` в ссылке на сайт); визиты считаются сами, без сторонних счётчиков.

Уведомления: колокольчик 🔔 (действия и заявки игроков, записи хроники ваших миров, покупки и отзывы, «партия ждёт» после недели без игры, испытание дня по желанию). Если не прочитали в игре за 10 минут — письмо-дайджест, не чаще раза в 6 часов; нужны `SMTP_URL` и `APP_URL`. В письме — ссылка отписки без входа; настройки — «Настройки» → «Письма на почту».

Здоровье платформы — в «Администрировании» → «Здоровье»: ходы и ошибки за час и сутки, медиана и p95 времени хода, кредиты, бэкапы. Алерты при всплеске ошибок, медленных ходах и проблемах с бэкапом уходят на `ALERT_EMAIL` (нужен `SMTP_URL`) и/или `ALERT_WEBHOOK_URL` (POST `{"text": "..."}` — подходит Slack, Mattermost, свой бот в Telegram).

### Без Docker

```bash
npm ci
cp .env.example .env
npm run build
npm start            # production: http://localhost:3000
```

Режим разработки с hot reload: `npm run dev`.

Попробовать без ключей ИИ и без оплаты: `LLM_PROVIDER=mock PAYMENTS_PROVIDER=mock npm run dev`, затем зарегистрируйтесь — первый аккаунт станет администратором. Демо-провайдер отвечает заготовками, и на нём видно весь интерфейс и мультиплеер.

## ИИ-провайдеры

Все запросы к ИИ идут **с сервера**, ключи в браузер не попадают.

| Провайдер | Переменные |
|---|---|
| Gemini | `GEMINI_API_KEY`, `GEMINI_MODEL` |
| OpenRouter | `OPENROUTER_API_KEY`, `OPENROUTER_MODEL` |
| OpenCode (подписка) | `OPENCODE_API_KEY`, `OPENCODE_MODEL` |
| Локальная / любая OpenAI-совместимая (Ollama, LM Studio, vLLM) | `LOCAL_MODEL_URL`, `LOCAL_MODEL_KEY`, `LOCAL_MODEL_NAME` |
| Демо без ИИ | `LLM_PROVIDER=mock` |

ИИ платформы настраивается в «Администрирование → ИИ платформы»; каждое пространство может подключить и свой ключ. Переменная `LLM_PROVIDER` жёстко фиксирует провайдера.
Если модель запущена на той же машине, что и Docker, укажите адрес `http://host.docker.internal:11434/v1`.

## Пространства, аккаунты и монетизация

- **Аккаунты мастеров**: вход по email и паролю (scrypt), сессия в httpOnly-cookie, защита от CSRF. Восстановление пароля — письмом (`SMTP_URL`) или ссылкой, которую выдаёт администратор платформы. Игрокам аккаунт не нужен: они заходят по ссылке на героя.
- **Пространства (тенанты)**: клуб, семья или команда. В каждом свои мастера, игры, ИИ и баланс. Роли:
  - **Владелец** — всё, включая оплату;
  - **Админ** — участники, ИИ, все игры пространства;
  - **Мастер** — свои игры, игры коллег видит, но не меняет.

  Приглашение — ссылка `/invite/…`, действует 7 дней и до 10 регистраций.
- **Первый зарегистрированный пользователь становится администратором платформы** (или те, кто указан в `SUPERADMIN_EMAILS`). Режим регистрации задаёт `REGISTRATION`: `open`, `invite` или `closed`.
- **ИИ пространства**:
  - **Свой ключ (BYOK)** — Gemini, OpenRouter или OpenCode. Ключ хранится зашифрованным (AES-256-GCM, `APP_SECRET`), в API отдаётся маской. Кредиты не тратятся.
  - **ИИ платформы** — ваш серверный ключ, расход списывается **кредитами** по фактическим токенам провайдера. 1 кредит = `CREDIT_TOKENS` взвешенных токенов, вывод в `OUTPUT_WEIGHT` раз дороже, ход мастера ≈ 10 кредитов.
- **Тарифы**:
  - «Бесплатный»: до 4 героев и игроков, `FREE_MAX_SESSIONS` сессий, `FREE_CREDITS` приветственных кредитов;
  - «Мастер» (подписка): до 8 героев и игроков, 500 сессий.

  Продаются пакеты кредитов и подписка, состав меняется через `BILLING_PRODUCTS` (JSON).
- **Оплата — ЮKassa** (`PAYMENTS_PROVIDER=yookassa`). Вебхук `POST /api/billing/webhook/yookassa` указывается в личном кабинете ЮKassa на событие `payment.succeeded`. Вебхуку не доверяем: статус перепроверяется запросом к API ЮKassa, зачисление идемпотентно. Чеки по 54-ФЗ включаются через `YOOKASSA_RECEIPT=true`. Для разработки есть `PAYMENTS_PROVIDER=mock`: оплата одним кликом.
- **Администрирование платформы** (в меню слева): пространства, выручка, расход за 30 дней, ручное начисление кредитов, включение тарифа, блокировка пространства, ИИ платформы.
- Защита от SSRF: свой URL модели в BYOK разрешён только при `ALLOW_BYOK_CUSTOM_URL=true` (self-host).
- Лимиты запросов к ИИ считаются по пользователю, попытки входа — по IP. За реверс-прокси включите `TRUST_PROXY=true`.

Старые сессии, созданные до появления аккаунтов, автоматически переходят в пространство первого администратора платформы.

### Вход через VK ID, Яндекс ID и Google

Кнопки появляются на экране входа, когда в окружении заданы ключи провайдера (`VK_CLIENT_ID/SECRET`, `YANDEX_CLIENT_ID/SECRET`, `GOOGLE_CLIENT_ID/SECRET`) и `APP_URL`. В настройках приложения у провайдера укажите адрес возврата `${APP_URL}/api/auth/oauth/<vk|yandex|google>/callback`.

- Первый вход создаёт аккаунт и пространство (с учётом режима регистрации и приглашений).
- С существующим аккаунтом склеивается только подтверждённая почта (Google, Яндекс); VK ID почту не подтверждает — для него новый аккаунт или привязка вручную.
- В «Настройки → Аккаунт» способы входа привязываются и отвязываются; без пароля можно задать его, последний способ входа отвязать нельзя.
- PKCE (S256) для всех трёх, state привязан к браузеру cookie.

## Оракул сессии

На старте игры модель генерирует таблицы под сеттинг сессии:
- для RPG — действия, темы, осложнения, NPC и детали мест;
- для сказки — помощники, чудеса и испытания.

Бросает по ним движок. Строки тянутся колодой, без повторов. Когда в колоде остаётся меньше 20%, движок в фоне догенерирует новые строки, без дублей и перефразировок уже имеющихся. Таблица ограничена `ORACLE_MAX_ROWS` строками, по умолчанию 150. Сверх лимита вытесняются самые старые уже выпавшие строки.

Мастер во вкладке Lore или «Книга» может догенерировать или перегенерировать любую таблицу. Можно добавить пожелание («партия спустилась в подземный город»), а можно поправить строки вручную. Для старых сессий таблицы создаются автоматически. Если генерация не удалась, используется встроенный запасной набор.

## Дисклеймер

На экранах мастера и игрока есть короткая строка о том, что контент генерирует ИИ. При первом входе показывается полный текст с подтверждением. Сам текст — в [docs/DISCLAIMER.md](docs/DISCLAIMER.md), дополнения оператора задаются через `DISCLAIMER_EXTRA` и `TERMS_URL`.

## Качество промптов

Аудит и описание исправлений — в [docs/PROMPT_AUDIT.md](docs/PROMPT_AUDIT.md). Оценить промпты на реальной модели:

## Как это устроено

```
браузер мастера ─┐                        ┌─ LLM (Gemini/OpenRouter/OpenCode/локальная)
телефоны игроков ┼─ REST + WebSocket ─ сервер ┤
                 │   (стрим, события)        └─ SQLite (сессии, состояние движка)
```

- `server/engine.ts`: игровой ход целиком на сервере. У каждой сессии своя очередь ходов, поэтому одновременные действия не затирают историю. Движок собирает промпт, добавляет честную проверку встречи и `[STATE]`, стримит ответ всем в комнате, разбирает JSON-блоки, применяет урон, золото и XP (State Authority), а при повышении уровня запускает отдельный ход со способностями.
- `server/tenancy.ts`: аккаунты, пространства, роли, приглашения, BYOK. `server/billing.ts`: кредиты, тарифы, ЮKassa, суперадмин.
- `shared/oracle.ts`: оракул вариативности (слоты действий, мотивы, идеи глав).
- `server/game.ts`: экономика, лут, база, экспедиции, фронты, мемориал, idle.
- `server/llm.ts`: провайдеры со стримингом и таймаутами, `server/mock-llm.ts` — демо и тесты.
- `shared/`: правила и промпты, парсеры ответов модели, серверные броски. Этот код общий для клиента и сервера.
- `src/`: React-клиент: экран мастера (`App.tsx`) и экран игрока (`components/CharacterView.tsx`).

## Прогон на настоящей модели

`e2e/play.mjs` проходит интерфейс как живой мастер и игрок: соло (генерация мира и героя, ходы, бросок), мультиплеер (игрок с телефона, бросок, раунд), сказку до книги. Отчёт с ответами мастера, проверками и скриншотами пишется в `e2e-report/`.

- Локально: `LLM_PROVIDER=mock MOCK_STYLE=demo npm start`, затем `npm i --no-save playwright && BASE_URL=http://localhost:3000 node e2e/play.mjs`.
- На настоящей модели: Actions → **Real AI play-test** (нужен секрет `OPENCODE_API_KEY`, `OPENROUTER_API_KEY` или `GEMINI_API_KEY`). Отчёт — в сводке запуска и артефакте `play-test`.

## Разработка

```bash
npm run lint     # tsc --noEmit
npm test         # vitest: парсеры, движок, e2e API (соло, мультиплеер, сказка, аккаунты, пространства, биллинг)
npm run build    # vite (клиент) + esbuild (сервер) → dist/, dist-server/
```

CI в GitHub Actions прогоняет lint, тесты, сборку, smoke-тест production-сборки и сборку Docker-образа.
